# H3で動くAiTuberを作る — 立ち絵から動画・口パク・会話まで

このリポジトリは制作手順だけを共有します。ソースコード、実行可能な設定、生成workflow、キャラクター素材、モデル重みは配布しません。各ツールは公式の配布元から、ご自身に適用される条件を確認して入手してください。

[English](README.md) | 日本語

[踏切AiTuber 踏切ワタルの体験デモ](https://wataru.highdrama.net/)も公開しています。録音済みの音声を選んだり、仕草のボタンを押したりして試していただけます。ライブのAI接続はありません。

「動画生成で作った滑らかな髪や体の動きを、配信でも使えないだろうか」。そんなところから始めた、踏切ワタルの制作記録です。素材の生成と再生時の制御を分け、H3の動画をブラウザでつなぎながら、音声に合わせて口を動かしています。

これは3DリグでもLive2Dモデルでもありません。動画を事前に作り、再生中に口元を合成する実験です。画像・動画・音声には生成AIを使用しています。このページは方法と再現用の設計を共有するもので、キャラクター素材やモデル重みの配布ではありません。

## 最初に知っておいていただきたいこと

完成形は9方向、正面と各方向を結ぶ16本の遷移、9種類の仕草、4種類の待機動作です。任意の動作へ自由に補間できるわけではなく、現在は正面を共通の接続点にしています。

ローカル版では、LLMの返答をIrodoriで音声化し、動作も選ばせています。体験デモは録音済みの合成音声を選ぶ方式です。閲覧者の操作でLLMやTTSを実行するものではありません。

## 1. キャラクターの基準画像を決める

最初のデザインはniji・journeyで制作し、GPT Imagesで構図の調整と多方向の参照画像を作りました。正面の基準画像では、同じカメラ位置・人物サイズ・背景を決めておきます。通常の待機では長い耳と両手が収まるようにしました。

今回のキャンバスは768×1344です。クロマキー用の緑背景を付けていますが、生成された背景なのでRGB値が完全に一定とは限りません。緑の目など、キャラクターの色を消してしまう可能性もあるので、単純な色抜きを万能とは考えない方がよさそうです。

体と顔の4方向の参照シートは、1枚の大きな画像のまま渡さず、各方向を分割して使います。R2Vでmaxを使う場合も先にサイズを調整します。短辺約1024pxを上限に縮小する設定は、以前の実験で使った出発点です。入力の細部が必要なら比較して決めてください。

## 2. まず正面と浅い斜めだけで試す

最初から全方向を作るより、正面・左浅め・その往復の2本でつながりを確認する方が進めやすかったです。うまくいってから正面、左右の浅め・斜め・横顔寄り、見上げ・うつむきへ広げました。15/30/60という名前は生成時の目標で、測定済みの角度ではありません。

画像編集では頭と耳の向きだけを変え、胴体、肩、衣装、手、カメラを維持するよう指示します。それでも画素単位では固定されないので、顔の位置・肩幅・人物の大きさを確認してから動画に進みます。

## 3. FL2VAで接続用の動画を作る

正面→斜めと斜め→正面は別々に生成します。今回の16本は768×1344、24fps、各73フレーム、約3.04秒でした。これはローカル実装で試した短尺設定であり、公式APIの尺の保証ではありません。INT8のFL2VAと対応するPDD8を使用しました。R2V用とFL2VA用のLoRAを混ぜないようにします。

首尾には対応する画像を入れ、カメラ固定、閉じた口、同じ緑背景を指定します。生成への指示では0.4秒から動き始めて2.5秒までに止まるようにしましたが、実際の停止時刻は出力を見て確認します。公式のプロンプトガイドに沿って映像・音響・音楽の記述を分けます。

ボタンを押した瞬間に人物が細く見える問題がありました。素材の横幅を確認し、このキャラクターでは中心基準の横1.0155倍補正で改善しました。この値は汎用の正解ではありません。補正する場合は口座標も同じ座標系で処理します。

## 4. 口は「同じモデルが描いたもの」から採る

以前は閉口ループにQwen-Image-Editで作った6種類の口を貼りました。仕組みは動きましたが、口の線・色・周囲の肌がH3の動画と合わず、作り直すたびに別の粗が出ました。

今回はH3で自然な会話文を発話させ、その動画から口元を切り抜く方針に変えています。単独の「あいうえお」では大口になりやすく、会話文の方が扱いやすい結果でした。左浅めは専用の発話動画も作り、同じ角度から採り直しました。

ただし、H3が日本語の母音を正しく描き分けたとは確認できていません。「い・え」の横引きや「う・お」の丸めが弱く、母音名を付けた素材にも近似が含まれます。「い」だけ笑って見える口も修正しました。別音声への汎用的な音素対応が完成した、という意味ではありません。

## 5. 元の口を追跡して消し、再生時に合成する

この試作では、基準画像とフレームの特徴点をSIFTで対応付け、RANSACで位置・縮尺・傾きを求めます。その後はLucas–Kanadeのオプティカルフローと、口周辺の暗い線による小さな補正で追います。アニメ顔では一般の顔検出が安定しなかったためです。

各フレームについて、口の中心x/y、幅、高さ、回転、縮尺、可視度、向きの近似値を保存します。閉口線は小さなマスクとOpenCVのinpaintで消し、元の閉じた口は透明PNGのアトラスに残します。無音時にはその閉口パッチを戻します。再生時にCanvasで発話用の口を合成します。

保存項目の意味と単位を揃え、再生するフレームに対応付けます。


回転して背面になる時や、顔が画面外に出る時はvisibilityを0にします。追跡できないフレームへ無理に口を貼らないことが大切でした。マスクや座標はキャラクターごとに検収が必要です。

## 6. 音声と口パクをつなぐ

既知の試作音声にはWhisper large-v3の単語時刻を使い、読みをモーラに分けて単語内を等分しました。これは音素の強制アラインメントではありません。

現在の自由な会話音声と公開用サンプルは声量による開閉です。音声を60fps相当の窓でRMSにし、開口量へ変換します。口形と開閉量を短い時定数で平滑化すると、パタパタした動きが和らぎます。ただし強くかけすぎると、口が音についてこなくなりました。

ユーザーの見え方に合わせ、口パク全体を24fps換算で6フレーム、約0.25秒延ばしています。最後の口だけを長く保持する方式ではありません。音声自体の速度は変更しません。

## 7. 仕草と自然な待機を増やす

手を振る、一回転、くねくね、おすまし、手でハート、逆立ち、ジャンプ、お辞儀、ハイキックを追加しました。一回転はカメラのオービットではなく、固定カメラの前で人物が回り、髪や服が遅れてついてくる動きです。

待機は髪を整える、少し横を見る、手を前で合わせる、重心を移すの4種類。各158フレーム、24fps、約6.58秒、768×1344のFL2VA PDD8です。首尾を同じ正面画像にします。完全な無限ループを保証するものではなく、終端を確認して使います。

通常は正面の静止を0.7〜1.7秒、浅い斜めの静止を2.5〜4.5秒にしています。大きな動作は最後まで再生し、途中で別クリップへ飛ばしません。仕草の接続にはフェードを使わず、最終フレームを保持します。角度遷移側には短いなじませ処理が残っています。

ジャンプでは一部フレームの背景に別の色が出たため補修しました。逆立ちやハイキックは、寄りの固定画角からはみ出す演出を許容しています。

## 8. IrodoriとローカルLLMを接続する

Irodori-TTS-v4.1-Smallでハスキーな女性声を設計しました。参照なしのVoice Designで作った合成声を、以後の発話の参照にします。途中で試したピッチ加工は機械的に聞こえたため不採用です。最終版は参照なし・ピッチ加工なしで作り直しました。名前は読み間違いを避けたい場面で「ふみきりわたる」と入力します。

Irodoriのモデルとcodecは起動時に一度ロードし、同じruntimeを発話ごとに再利用します。ローカル専用サーバーにし、生成要求を直列化します。Windowsの自動起動サービス登録とは別です。

会話接続にはAITuber OnAirの公開パッケージ`@aituber-onair/chat` 0.54.0を利用しました。OnAirの完成アプリや同梱キャラクターを移植したものではありません。最初は別マシンのGLM-5.3-Flash-EXL3を使い、その後RTX 5090上のLM Studio / openai/gpt-oss-20bへ切り替えました。

返答は読み上げ本文と動作名に分けます。使用できる動作だけを許可し、自由なコード実行は渡しません。


gpt-ossではJSONを文章だけで指定するとLM Studioのpeg-nativeエラーが出たため、response_formatにJSON Schemaを指定すると今回の環境では通りました。一般的な必須条件とまでは言えません。

得意技を聞かれてハイキックや逆立ちを紹介した場合は、台詞の終了後にその動作を再生します。自動動作オフや大きな動作オフは尊重します。同時に複数の仕草を走らせないよう、プレイヤー側で順番を管理します。

短い挨拶の実測ではLLM約0.39秒＋TTS約1.13秒、API全体約1.55秒でした。TTS単体は常駐後初回1.70秒・2回目0.95秒。文章、キャッシュ、GPU負荷、声の設定で変わる少数試験です。配信開始までの普遍的な遅延保証ではありません。

## まず自分のキャラクターで試すなら

1. 同一キャンバスの正面と浅い斜めを用意します。
2. 往復2本のFL2VAを生成し、サイズの跳びを先に確認します。
3. 正面と斜めで自然な会話文を発話させ、口素材を採ります。
4. 数十フレームで口の消去・追跡・合成を確認します。
5. 自作または権利を確認した音声で、声量による開閉をつなぎます。
6. うまく見えてから方向と仕草を増やし、最後にLLMを接続します。

ComfyUIやカスタムノードの版によってAPIグラフは変わります。まず手元のGUIで1本生成できるworkflowを保存し、API形式で書き出してから自動化するのがおすすめです。首尾画像、尺、解像度、LoRAのタスク、プロンプトの参照順を実行直前に確認します。

## 公開デモとローカル版は分ける

体験版には録音済みの自己紹介・ハイキック・逆立ちの音声を置きます。モデル、APIキー、ローカルIP、チャット履歴、生成サーバー、ファイル入力は含めません。ダウンロード機能は提供しませんが、ブラウザへ配信したデータの取得や録画を完全に防げるわけではありません。

Sitesを含むホスティングは、素材の権利やライセンスの条件を置き換えません。H3生成物の公開は制作者が確認した条件に基づいて行います。この記録は、すべての利用者にライセンス不要と保証するものではありません。利用するモデルとサービスの現行条件を確認してください。

## 残っている課題

未知の音声の母音認識、発音に連動する顎・頬の変形、独立した表情と目パチ、斜め同士の直接遷移は未実装です。動画中の目パチは生成された動きです。衣装の細部や手の形が変わることもあります。ここまでの見栄えは、生成一発ではなく、素材の選別と局所的な修正を重ねた結果です。
